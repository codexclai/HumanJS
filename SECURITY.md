# Security policy

## Reporting a vulnerability

Do not publish credentials, exploit details, private data, or an actionable vulnerability in a public issue.

Use GitHub private vulnerability reporting for this repository when available. If it is not enabled, contact the repository owner through an authenticated private GitHub channel and ask for a private disclosure route. Do not include secrets in the initial report.

## Supported scope

Report security issues affecting the HumanJS repository, build workflows, dependency configuration, Rust/Python/C/C++ interfaces, persistence, input validation, resource management, and release processes.

The project is early-stage. No production support or security response-time guarantee is implied.

## Disclosure expectations

Provide the affected commit or revision, environment, reproduction steps, impact assessment, and a safe proof of concept. Allow reasonable time for investigation and remediation before public disclosure.

Do not test against systems or data that you do not own or have permission to assess.
